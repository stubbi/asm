# Report a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/stubbi/asm/security/advisories/new) for a security defect.
Do not put exploit details, credentials, or private data in a public issue.

Include the affected version, target, command, and a small reproduction.
Describe the impact and any required preconditions.
Use harmless test data in the reproduction.

If the private form is unavailable, open an issue that asks for a private reporting route.
Do not include the vulnerability details in that issue.

## Support scope

Asm is an early alpha.
Security fixes target the latest release and the main branch.
There is no guaranteed response time or support period yet.
The maintainers will record a defined policy before a stable release.

Read [the security model](docs/specs/security.md) for the implemented checks and planned controls.
A package's checksum, signature, test result, or proof does not establish that the whole package is safe.
The [maintenance guide](docs/maintaining.md#respond-to-an-incident) describes incident response and recovery.
