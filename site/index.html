GET STARTED

Install Asm.

The installer selects a published executable for your operating system and CPU. Install it for your user account, then run the first-project commands above.

Version 0.5.0 supports Linux x86-64, Linux ARM64, and Apple Silicon macOS 15 or later. Intel macOS is unsupported.

A binary installer will appear here after the site checks a published CLI release. You can build from source now.

Build from source

Install Git, Make, and Python 3.11 or later. Linux needs GNU binutils; macOS needs Xcode Command Line Tools. These commands install Asm for your user account.

>_ BUILD FROM SOURCE
# Linux or Apple Silicon macOS · native build tools
git clone https://github.com/stubbi/asm.git &&
cd asm &&
make &&
make install PREFIX="$HOME/.local" &&
export PATH="$HOME/.local/bin:$PATH" &&
asm version

THE PACKAGE MODEL

The target is part
of the package.

A useful assembly routine should be easy to reuse. Its package must state which machine it supports and how other code can call it.

WHY Asm

Make the useful
work reusable.

Software should work well for its users and cost less to run. Assembly can give developers direct control over how a machine does that work.

Our working assumption is that AI-assisted development may make assembly practical for more projects. It may also reduce the cost of ports. Both claims need evidence.

Generated code still needs review and verification. Performance claims need reproducible measurements, including results that show no improvement. Asm is building the shared package, release, and evidence tools for that work.

A measured example

An asmwc experiment measured default counting on a 128 MiB text file. On Apple M3 with macOS 15.6.1, median time was 15.234 ms for optimized assembly and 68.468 ms for native Rust. Each implementation had 24 samples with a warm file cache. The comparison includes algorithm, I/O, and startup differences. Asm checked the published records; we have not reproduced the experiment.
