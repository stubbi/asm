# V2 release implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` for the authorized release work. Track the checks below before publication.

**Goal:** Release the signed V2 client and hostable registry components with reproducible bytes, complete source, and explicit operating limits.

**Architecture:** Ordinary 0.7 builds include V2 assembly logic and the existing transport and cryptography adapter. Keep self-update trust activation separate. Reuse the current native qualification and immutable publication pipeline.

**Tech stack:** Native x86-64 and AArch64 assembly; maintained Go TUF and Sigstore libraries; existing Python operator and release tools.

**Specifications:** [V2 distribution](../../specs/registry-v2.md), [publication](../../specs/publication.md), [security](../../specs/security.md), [release procedure](../../maintaining.md).

## Outcome and constraints

The consumer receives the same full client from an ordinary source build and the published release.
An operator receives the source and dependencies needed to host a publisher or static mirror.
This follows dependable reuse, resource care, and evidence-based claims in the brand foundation.
The accepted trade-off is a larger executable that embeds maintained transport and cryptography code.
It avoids another required runtime installation for explicit V2 registry operations.

- Application and package logic remain in assembly.
- Preserve V1 commands, locks, feeds, immutable records, and historical licenses.
- Keep the released hosts at Linux x86-64, Linux ARM64, and Apple Silicon macOS 15 or later.
- Keep `trusted_distribution` disabled until its separate provisioning conditions hold.
- Keep explicit registry identity, independently selected roots, protected state, and mirror authority separation.
- Require exact-source native tests, two clean builds, artifact digests, provenance, and published first-project checks.
- Never execute candidate artifacts in the write-capable publication job.
- Keep main rulesets, required checks, production holds, and deployment access rules unchanged.
