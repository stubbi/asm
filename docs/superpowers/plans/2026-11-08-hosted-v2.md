# Hosted V2 implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development for independent tasks. Keep activation separate from preparation evidence.

**Goal:** Let an operator deploy the existing assembly publisher and signed distribution without broad credentials or extra application services.

**Architecture:** PostgreSQL retains publication authority and task fencing. The assembly publisher receives requests through a same-Pod proxy. Secretless, bounded checker Jobs inspect packages. Existing operators retain objects and publish signed metadata to static storage.

**Tech stack:** Linux AMD64 assembly, reviewed libmicrohttpd and PostgreSQL 16.15 clients, PostgreSQL 18.6 server qualification, maintained cryptography, Python operations, Kubernetes.

**Spec:** `docs/specs/registry-v2.md`, `docs/specs/security.md`, `docs/trusted-distribution.md`, and `docs/hosting.md`.

## Global constraints

- Keep CLI and HTTP application logic in assembly.
- Keep production root keys outside this workspace, CI, and Kubernetes.
- Keep the registry root separate from the disabled self-update root.
- Retain strict private-file ownership, permission, ACL, and symlink checks.
- Keep ScienceHub activation suspended until its qualification gates pass.
- Use scoped storage and database identities. Never reuse ScienceHub application credentials.
- Record source revisions and artifact digests. Preserve failed and missing evidence.

## User outcome and trade-offs

Publishers can use a project from any supported Git host. Enrollment binds an owner identity, not a hosting account.
Consumers receive authenticated immutable releases and complete graph locks.
The guiding principles are dependable reuse, resource care, and evidence before claims.
Manual enrollment avoids an additional login service. It retains an explicit operator recovery task.
Static distribution avoids application traffic for each download. Storage requests and replication still have costs.
