## Global constraints

- Keep V1 records, published bytes, and self-update trust behavior unchanged.
- Keep package parsing, target policy, mirror retries, publication requests, and installation in assembly.
- Use exact registry, root, package, release, envelope, target, and artifact bindings.
- Preserve 64 MiB artifacts, 128 MiB publication tasks, and the specified metadata and credential limits.
- Use fixture identities only; do not create production root keys or activate deployment holds.

## Review focus

- An expired worker must not replace a newer metadata or critical policy head.
- A changed root or registry must not silently adopt existing trust or installed state.
- An uncertain request must retain its identity and immutable bytes for a safe retry.
- A corrupt mirror must not cause an unsigned fallback or conceal an existing destination.
- Credential files, signing keys, and private staging must remain outside package execution and public storage.
